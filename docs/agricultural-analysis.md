# CropSuite agricultural analysis

The pilot comparison is exploratory decision support, not a validated planting recommendation. Farmers should check soil, water, variety, timing and local advice before planting. It does not predict yield.

## Data

- FAO GAEZ v5 `RES05-SXX30AS`: crop suitability index (0–10,000), all land in a 30-arc-second grid cell, 2001–2020 AgERA5 climate baseline. Low-input rainfed (`LRLM`) and fully irrigated (`LILM`) layers are included for maize (`MZE`), Phaseolus bean (`PHB`), sorghum (`SRG`), soybean (`SOY`) and groundnut (`GRD`). Codes and file names were checked against the [official RES05 catalogue](https://data.apps.fao.org/catalog/dataset/514c92d5-9e01-4c70-814a-80ea1ca9fe6a/resource/768b08ad-be9c-427a-84be-3a3d6dd7835a/download/_readme_res05.xlsx). The stored rectangular clip covers the Rwanda pilot bounding box and is not an administrative boundary. Recreate it with `python scripts/prepare-gaez-kayonza.py` (requires Rasterio and NumPy). A grid cell is not a soil test or field measurement. An irrigated scenario assumes reliable full irrigation; “sometimes” does not select it.
- NASA POWER: `PRECTOTCORR` and `T2M` for the most recent completed calendar year, UTC, with an entire year required before aggregating. These are historical gridded estimates, not forecasts. Seasonal climatology, minimum/maximum temperature and radiation are not yet implemented.
- Meteomatics: 48 consecutive right-aligned hourly `precip_1h:mm` windows plus `t_2m:C` and `wind_speed_10m:ms`. The sum is accepted only if every expected hourly timestamp is present. Forecast issue time is unknown; retrieval time and valid interval are retained. Data outside that interval is not forecast. Credentials are server-only environment variables.

The environmental endpoint accepts `POST /api/environment` with `lat`, `lon`, and optionally `water`, `selected`, `previous`, `allowAlternatives`, and `plantingMonth`. Coordinates are validated globally. Within the Rwanda clip, FAO pixels are read locally; elsewhere the server reads the required pixel from the same official global GeoTIFF using HTTP range requests. This still only covers the five documented crops and two management scenarios. Ocean, missing, unsupported or inaccessible cells return an unavailable status. External failures are isolated. Caches and request limits are process-local, not durable or distributed; production needs a shared rate limiter and quota monitoring.

Country names and map-centering points use the [countries dataset](https://github.com/mledoze/countries) (ODbL); Rwanda districts and approximate map centres are from the [National Institute of Statistics of Rwanda's open 2022 district boundaries](https://gis-server.statistics.gov.rw/server/rest/services/Hosted/District_Boundary_2022/FeatureServer/0). Selecting an area moves the map but never substitutes its centre for a farm coordinate. The Kinyarwanda interface copy should be reviewed with native-speaking farmers and agricultural advisers before production use.

## Comparison rule

Only crops with a usable, non-zero GAEZ baseline index in the selected scenario enter the comparison. An index of zero is excluded **under that historical model scenario**, not declared impossible on the farmer's actual land. Unsupported crops, pixels outside the clip and missing cells remain unavailable. For uncertain or intermittent irrigation the system shows both baseline scenarios, but does not assume either one or rank a sequence.

For every three-crop sequence, the exploratory ordering adds the three baseline indices, subtracts 500 index units for each adjacent repeated crop family (including the preceding crop), and adds 250 units if the first crop was selected by the farmer. Maize and sorghum are cereals; common beans, soybeans and groundnuts are legumes. The top three sequences are displayed. The weights are product assumptions, not FAO-approved or independently validated. They do not represent a percentage yield, probability of success or forecast, and do not model particular planting dates, soil tests, disease, markets, actual water supply or crop durations. Forecasts and NASA annual summaries are shown separately and are deliberately not counted again in the ranking. The same baseline is reused for every future season, which is why every sequence is provisional.

The GAEZ values reflect a single-crop model; they do not validate multi-cropping or the proposed sequence. No stronger suitability or “best crop” claim should be made without locally validated agronomic rules, seasonal climatology and field evidence.

## Verification

Build with `npm run build`. Start the application and run `node --test tests/environment-integration.test.mjs`. The integration test compares the Kayonza sample grid value against an independently read FAO GeoTIFF, tests both water scenarios, missing data, ranking, invalid coordinates and provenance. The tests contact upstream services; they do not establish the scientific validity of the weights. Local environments with an institutional TLS proxy may need the host's trusted CA (for Node versions supporting it, `NODE_OPTIONS=--use-system-ca`).
# Global verification and climate context

NASA POWER now requests five complete calendar years of daily precipitation, 2 m temperature and all-sky shortwave energy for the selected coordinate. The app sums daily rainfall for each month and reports the five-year monthly average and observed minimum/maximum of those five monthly totals. Temperature is a monthly average; solar energy is in MJ/m²/day. Incomplete precipitation or temperature histories are marked unavailable rather than filled with invented values. These are coarse historical estimates, not a forecast or field measurement. The planting-month comparison is context only and is not part of the rotation score.

Remote FAO reads require HTTP range support and an EPSG:4326 30-arcsecond grid. Global requests are limited to three concurrent reads per process, identical in-flight cells are shared, and successful results are cached. Missing cells, unsupported crops, invalid grids and upstream failures have separate reason codes; a real zero remains a zero. Per-process limits and caches are not distributed rate limiting for a production deployment.

Live checks on 15 November 2026 used the coordinates in `tests/global-live.test.mjs`. Meteomatics forecasts and NASA histories were available in all six locations. The rainfed FAO raster had positive values and three exploratory sequences for Kayonza and New Delhi; the tested city-centre points in Nairobi, Accra, São Paulo and Paris yielded zeros and/or no-data, so no rotation was generated. These are point-specific checks, not evidence of coverage or lack of coverage across an entire country. The recommendations remain an unvalidated heuristic and require local agronomic review.


## Guided example

The farmer setup offers an explicit guided example using `lib/farmer/demo-snapshot.json`, captured for the Kayonza example point on 16 November 2026. It uses fixed example answers and does not call the environment endpoint. The stored weather forecast is an old snapshot, never current weather; example mode and saved example plans are labeled accordingly. The example is a demonstration of the interface, not a field-specific recommendation. Leaving the example restores the user's original unsaved farm answers. Sample selection is deliberately read-only so a changed input cannot be presented alongside an unrelated fixed result.
